The Checks resource lets you create and manage check definitions — the templates that describe the type of verification you want to perform. You can create checks of different types (background, identity, or credit), list all checks in your account, and retrieve a specific check by its ID. Results are generated separately when a check is run; see the [Results reference](/api-reference/endpoints/results) for details.

---

## List all checks

<ParamField query="page" type="integer">
  The page number to return. Defaults to `1`.
</ParamField>

<ParamField query="per_page" type="integer">
  Number of results per page. Defaults to `20`. Maximum is `100`.
</ParamField>

<ParamField query="status" type="string">
  Filter checks by status. Accepted values: `active`, `archived`.
</ParamField>

Returns a paginated list of all checks in your account, ordered by creation date descending.

```bash curl
curl https://api.wearecheck.com/v1/checks?page=1&per_page=20 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

**Example response — 200 OK**

```json
{
  "data": [
    {
      "id": "chk_01HXYZ123",
      "name": "Identity Verification",
      "type": "identity",
      "status": "active",
      "description": "Standard identity check",
      "created_at": "2024-01-15T10:30:00Z",
      "updated_at": "2024-01-15T10:30:00Z"
    }
  ],
  "meta": {
    "page": 1,
    "per_page": 20,
    "total": 1
  }
}
```

<ResponseField name="data" type="array">
  An array of check objects.

  <Expandable title="properties">
    <ResponseField name="id" type="string">
      Unique identifier for the check, prefixed with `chk_`.
    </ResponseField>
    <ResponseField name="name" type="string">
      Human-readable name for the check.
    </ResponseField>
    <ResponseField name="type" type="string">
      The check type. One of `background`, `identity`, or `credit`.
    </ResponseField>
    <ResponseField name="status" type="string">
      Current status of the check. One of `active` or `archived`.
    </ResponseField>
    <ResponseField name="description" type="string">
      Optional description provided at creation time.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when the check was created.
    </ResponseField>
    <ResponseField name="updated_at" type="string">
      ISO 8601 timestamp of the most recent update.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="meta" type="object">
  Pagination metadata.

  <Expandable title="properties">
    <ResponseField name="page" type="integer">
      The current page number.
    </ResponseField>
    <ResponseField name="per_page" type="integer">
      Number of items per page.
    </ResponseField>
    <ResponseField name="total" type="integer">
      Total number of checks matching the query.
    </ResponseField>
  </Expandable>
</ResponseField>

## Create a check

<ParamField body="name" type="string" required>
  A human-readable name for the check. Used to identify it in the dashboard and API responses.
</ParamField>

<ParamField body="type" type="string" required>
  The type of verification to perform. Accepted values: `background`, `identity`, `credit`.
</ParamField>

<ParamField body="description" type="string">
  An optional free-text description of what this check is used for.
</ParamField>

Creates a new check definition. Once created, the check can be run to produce results.

```bash curl
curl -X POST https://api.wearecheck.com/v1/checks \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Identity Verification",
    "type": "identity",
    "description": "Standard identity check"
  }'
```

**Example response — 201 Created**

```json
{
  "data": {
    "id": "chk_01HXYZ123",
    "name": "Identity Verification",
    "type": "identity",
    "status": "active",
    "description": "Standard identity check",
    "created_at": "2024-01-15T10:30:00Z",
    "updated_at": "2024-01-15T10:30:00Z"
  }
}
```

## Get a check

<ParamField path="id" type="string" required>
  The unique identifier of the check to retrieve. Must be prefixed with `chk_`.
</ParamField>

Retrieves a single check by its ID.

```bash curl
curl https://api.wearecheck.com/v1/checks/chk_01HXYZ123 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

**Example response — 200 OK**

```json
{
  "data": {
    "id": "chk_01HXYZ123",
    "name": "Identity Verification",
    "type": "identity",
    "status": "active",
    "description": "Standard identity check",
    "created_at": "2024-01-15T10:30:00Z",
```
